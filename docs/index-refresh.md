# 파일 인덱스 자동 재빌드 가이드

## 개요
- FastAPI 백엔드가 시작될 때만 파일 인덱스를 생성하던 문제를 해결했습니다.
- `INDEX_REFRESH_INTERVAL_MINUTES` 환경변수(기본 30분)에 맞춰 주기적으로 인덱스를 다시 구축합니다.
- 백엔드 종료 시 백그라운드 작업을 취소하여 잔여 스레드가 남지 않습니다.

## 설정
- `api/config.py` 에서 `INDEX_REFRESH_INTERVAL_MINUTES` 값을 `os.getenv`로 읽어옵니다.
- `start.ps1`, `start.sh` 에 기본값 `30` 이 추가되어 있습니다. 운영 환경에 맞춰 값만 조정하면 됩니다.
- 0 이하로 설정하면 자동 재빌드가 비활성화됩니다.

## 동작
- 서버 시작 시 즉시 한 번 인덱스를 구축하고, 이후 설정된 주기마다 `_index_refresh_loop` 가 재빌드를 실행합니다.
- 사용자 요청이 진행 중이면 잠시 대기하며, 기존 재빌드가 진행 중일 경우 로그만 남기고 건너뜁니다.
- 재빌드 시작/종료 로그:
  - `🔁 [INDEX] 자동 재빌드 시작`
  - `🛑 [INDEX] 자동 재빌드 루프 종료` (서버 종료 시)

## 확인 방법
1. (선택) `INDEX_REFRESH_INTERVAL_MINUTES=1` 로 설정 후 서버를 실행합니다.
2. 새 파일을 `PROJECT_ROOT` 아래에 추가합니다.
3. 1~2분 뒤 `/api/files/all` 엔드포인트를 호출해 파일이 인덱스에 포함됐는지 확인합니다.
4. 테스트 종료 후 `INDEX_REFRESH_INTERVAL_MINUTES` 값을 원래대로 복원합니다.

## 참고
- 기존 수동 인덱스 재빌드 흐름(`build_file_index_background`)은 그대로 유지됩니다.
- 백그라운드 작업은 서버 종료 이벤트에서 안전하게 취소됩니다.
