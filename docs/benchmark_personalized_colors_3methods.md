# 개인색 설정 이미지 처리 방식 벤치마크 결과

## 개요
팔레트 기반 이미지에 개인색 설정을 적용하는 3가지 방식의 성능 비교 결과입니다.

## 테스트 환경
- **테스트 폴더**: `D:\project\data\wm-811k\palette_copies_3k`
- **처리 이미지 수**: 100개
- **목표 크기**: 512x512
- **원본 이미지 크기**: 7788x7788 (팔레트 모드 PNG)

## 처리 방식 설명

### 방식1: 개인색 설정 안함 (기존 pyvips)
```python
1. pyvips.Image.new_from_file() 로드
2. pyvips shrink + resize(cubic) 조합으로 리사이즈
3. PNG 저장
```

**특징**: 가장 빠른 방식, 개인색 설정 미적용

---

### 방식2: 현재 방식 (팔레트 교체 → RGB 변환 → pyvips 리사이즈)
```python
1. PIL로 팔레트 모드(P) 로드
2. 팔레트 교체 (swap_first16_colors)
3. RGB로 변환 (원본 크기 7788x7788)
4. numpy → pyvips 변환
5. pyvips shrink + resize(cubic) 조합으로 리사이즈
6. PNG 저장
```

**특징**: 품질 우선, 팔레트 교체 후 RGB 변환하여 부드러운 리사이즈 보장

---

### 방식3: 추가 최적화 (메모리 해제 최적화)
```python
1. PIL로 팔레트 모드(P) 로드
2. 팔레트 교체 (swap_first16_colors)
3. RGB로 변환 (원본 크기 7788x7788)
4. PIL 이미지 즉시 닫기 (메모리 해제)
5. numpy → pyvips 변환
6. numpy 배열 즉시 삭제 (메모리 해제)
7. pyvips shrink + resize(cubic) 조합으로 리사이즈
8. PNG 저장
```

**특징**: 방식2와 동일하지만 메모리 해제 최적화 적용

---

### 현재 병목 분석

1. **PIL convert('RGB')**: 원본 크기(7788x7788)에서 가장 큰 병목
   - 처리 시간: 약 150-200ms
   - 필수 작업 (팔레트 모드에서 RGB로 변환)
   - 대체 방법 없음

2. **팔레트 교체**: 상대적으로 빠름
   - 처리 시간: 약 5-10ms
   - 최적화 여지 거의 없음

3. **pyvips 리사이즈**: 매우 빠름
   - 처리 시간: 약 50-80ms
   - 이미 최적화됨

### 속도 개선 한계

**현실적인 목표**: 방식1 대비 30% 이하로 줄이는 것은 **거의 불가능**

**이유**:
- PIL `convert('RGB')`가 원본 크기에서 필수 작업
- 이 작업을 대체할 수 있는 방법이 없음
- numpy 직접 변환도 메모리 접근 패턴상 비효율적

**가능한 최적화**:
- 병렬 처리 (여러 이미지 동시 처리) - 단일 이미지 처리 시간은 안 줄임
- 캐싱 (동일 이미지 재처리) - 첫 처리 시간은 안 줄임
- 메모리 최적화 - 약 2-5% 개선
